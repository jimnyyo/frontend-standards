# 호스트 CMS 실측 기록 — CBS 이벤트 페이지

`cbs.co.kr/event/view/*` 에 블록을 삽입할 때 실제로 확인된 동작입니다. 2026-08-07 실측.

다른 호스트에 작업할 때는 이 파일을 템플릿 삼아 **같은 항목을 직접 측정해서** 새로 만드세요. 값을 그대로 가져다 쓰지 말 것 — 항목 목록만 재사용합니다.

---

## 측정해야 하는 것 (호스트 불문 공통)

1. 템플릿이 URL로 갈리는가, User-Agent로 갈리는가
2. PC/MO가 본문 필드를 공유하는가
3. 템플릿 래퍼가 내 블록에 어떤 규칙을 거는가 (특히 `img`)
4. 레이아웃에 `min-width` 류 강제가 있는가
5. 서버가 페이지를 캐시하는가

---

## CBS 실측 결과

### 1. 템플릿은 URL이 아니라 User-Agent로 갈린다

같은 주소가 UA에 따라 다르게 나옵니다.

| | 데스크톱 UA | 모바일 UA |
|---|---|---|
| CSS | `/css/pc/*` | `/css/mobile/*` |
| 래퍼 | `<div class="box company-box02"><div class="max-cont">` | `<div class="box ">` (클래스 빈 값) |
| viewport 메타 | 없음 | 있음 |

**주소를 나눠도 자동 분기가 안 됩니다.** 반응형은 리다이렉트가 아니라 이 신호로 판별해야 합니다.

### 2. 본문 필드는 PC/MO가 공유한다

두 응답의 삽입 블록이 바이트 단위로 동일합니다. → PC용/MO용 코드를 따로 넣을 수 없습니다.

SKILL.md §5의 두 기법(`media='not all'`, `<picture>` 1×1 GIF)이 필요한 이유가 이것입니다.

### 3. PC 템플릿만 이미지 폭을 강제한다

```css
/* /css/pc/box.css */
.company-box02 .max-cont img { width: 100%; height: auto; display: block; }   /* (0,2,1) */
```

- 래퍼는 템플릿이 찍는 것이라 에디터에서 못 지웁니다.
- 이기려면 `.hw26 .hw26_wrap` 처럼 접두어를 겹쳐 **(0,3,x)** 까지 올려야 합니다.
- **모바일 템플릿엔 이 규칙이 없습니다.** "모바일만 멀쩡한" 증상의 원인입니다.

### 4. PC 템플릿은 `main { min-width: 1200px }`

`/css/pc/layout.css:360`.

창을 줄여도 상자가 안 줄어듭니다. 반면 `@media`는 뷰포트 기준이라, 창을 640px로 줄이면 **1200px 상자 안에 모바일 레이아웃이 그려집니다.**

→ 브라우저 창 줄이기는 이 호스트에서 유효한 모바일 테스트가 아닙니다. UA를 바꿔서 확인해야 합니다.

### 5. 서버는 이 페이지를 캐시하지 않는다

`Cache-Control: no-store, no-cache`.

수정이 안 보이면 캐시가 아니라 **CMS 저장/발행이 안 된 것**입니다. 캐시 무효화를 시도하기 전에 발행 상태부터 확인하세요.

## 자산 호스팅

| 종류 | 호스트 | 비고 |
|---|---|---|
| 이미지 | `img.cbs.co.kr/cbs/event/<번호>/<캠페인>/` | |
| 폰트 | `file2.nocutnews.co.kr/fonts/` | `ACAO: *` 라 `cbs.co.kr` 에서 불러도 CORS 문제 없음 |

폰트를 다른 곳에 올릴 경우 CORS 헤더를 먼저 확인하세요. 서브셋이 아직 안 올라갔을 때를 대비해 `src` 두 번째에 원본 CDN을 넣어 둡니다.

## 검증 방법

헤드리스 Chrome으로 **라이브 HTML을 받아 삽입 블록만 교체해 렌더링**하면 CMS 환경을 그대로 재현할 수 있습니다. 로컬 `index.html`을 그냥 여는 것과 달리 템플릿 래퍼·호스트 CSS가 함께 적용되므로, 위 3·4번 문제가 실제로 재현됩니다.

UA를 바꿔가며 두 번 확인하세요 — 3번과 4번이 PC 템플릿에서만 나타나기 때문입니다.
